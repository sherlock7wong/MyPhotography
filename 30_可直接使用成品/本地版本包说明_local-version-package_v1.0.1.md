## 解压使用

解压 ZIP 到新的空目录，进入 `个人摄影网站_photography-site_v1.0.1`，运行：

```powershell
node start-server.js
```

打开 `http://127.0.0.1:5173/Home/index.html`，后台为同域 `/admin/index.html`。若原网站正在占用5173端口，可先在当前PowerShell设置 `$env:PORT='5188'`，再启动并访问对应端口。导出包无需恢复原项目的Windows目录联接；服务会从 `20_源码与运行工程` 读取页面。

导出包不含真实本机数据库和上传媒体，因此首次启动使用源码中的初始内容。原项目本机数据、Cloudflare/D1/KV/B2内容及原始照片仍在原位置，未迁移或删除。包内也不含私有凭据文件、认证会话、依赖缓存、原始验收截图和90/99中的恢复材料；沿用源码中已有的本地默认配置。

后端构建在 `20_源码与运行工程/site-deployment` 内按现有锁文件运行 `npm.cmd ci`，再运行 `npm.cmd run build:pages`。这一步仅生成本地产物；发布需要原账号的配置和另行授权。

## 仅用 Git bundle 恢复

在交付目录中，选择尚不存在的恢复路径，依次执行：

```powershell
git clone --branch main './前端与文档_frontend-docs_v1.0.1.bundle' './恢复目录'
git clone --branch main './云端后端_cloud-backend_v1.0.1.bundle' './恢复目录/20_源码与运行工程/site-deployment'
```

两个仓库分别执行 `git show v1.0.1 --no-patch` 查看版本。根仓库故意忽略普通嵌套后端，故只恢复第一个bundle会缺少后端。
