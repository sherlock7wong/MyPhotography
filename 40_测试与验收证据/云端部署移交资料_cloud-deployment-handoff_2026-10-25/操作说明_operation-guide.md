# 个人摄影网站操作使用说明

适用项目：WonG Visual Archive · `F:\个人主页`  
本轮更新日期：2026-10-25（Asia/Shanghai）
使用方式：阅读本文件，或双击同目录的同名 `.html` 阅读版；HTML 可通过浏览器“打印 → 另存为 PDF”导出。

当前后台使用中文，按首页、关于页、项目页、摄影页和联系页编辑；City Humanity 在摄影页的分类管理中统一维护。**通过根目录服务打开的 5173 网站，默认使用“本机网站（共享保存）”：前后台经真实本机 HTTP 接口读写同一份文件，换浏览器也能读取保存后的内容。**云端已采用 Pages、D1 与私有 B2；本机和云端为独立环境，分别按下节入口使用。

## 云端后台与照片上传（2026-10-25）

- [打开正式网站](https://wong-photography-4a45fb46.pages.dev/Home/index.html) · [打开云端后台](https://wong-photography-4a45fb46.pages.dev/admin/index.html)。这是免费平台子域名；关闭本机服务后仍由云端提供服务。
- 使用正式站管理员账号登录；账号资料只在本机的99目录“正式网站部署”下的“后台登录凭据_admin-login-credentials.json”保存，本说明不复制口令。云端后台显示“本站云端接口”。
- 在对应页面的上传按钮选择照片，不需要提供本地文件夹，也不会自动监控目录。支持 JPEG、PNG、WebP、GIF；原图上限50,000,000字节，GIF上限8,000,000字节。本机5173仍为8 MB，不会自动同步原图到云端。
- 浏览器自动生成展示图与缩略图，原文件不改动。原图保存在私有桶，作品编辑中可“下载云端原图”；访客只能读取已公开内容使用的派生图。网页“原片与成片”中的原片仍是公开对照副本。
- 等待“原图和网页图片已保存在云端”，再点“保存本页到云端”。上传本身不会把未保存的作品资料直接发布；“显示/Published”内容在保存后可公开，草稿不公开。替换图片和移除作品都不会自动删除云端文件。
- 上传回包中断时，恢复编号保留在当前浏览器。刷新后重新选择同一原文件可继续已确认进度；已成功角色不会重复上传。提示结果待核实时保留现场，不清除本站浏览器数据或反复重传。
- 后台显示已用及待确认空间，网站预算9 GB；不足时拒绝新上传。该数字是本站账本，桶内旧版本、其他工具上传和历史样本仍占免费空间；B2账户caps继续保留，不能承诺10 GB可容纳全部1,000张原图。
- 云端CMS和本地5173是两个独立环境，修改一处不会自动同步另一处。云端JSON导出不包含原图；全量恢复还需要私有媒体与路径映射。
- 用户已在本次要求的大陆手机流量、关闭Wi-Fi和代理环境下确认正式首页、摄影页及照片正常；本次未提供运营商名称，其他运营商及长期稳定性仍未验证。

## 1. 先确认数据来源与使用范围

| 使用范围 | 内容保存到哪里 | 怎样判断 |
| --- | --- | --- |
| 本机网站（共享保存） | 本机服务的数据文件和媒体目录，由同源 API 统一读取、保存 | 后台左下角显示“本机网站共享内容”；同一运行服务的不同浏览器读取同一份内容 |
| 正式云端网站 | Pages/Worker、D1 与私有 B2 | 打开上方正式网址，后台显示“本站云端接口”；本机数据不会自动同步 |

默认数据文件为 `20_源码与运行工程/.local-db/wong-cms.json`，上传图片位于同目录下的 `media/`，写入前的恢复副本位于 `recovery/`。这些私有内容不纳入 Git，不作为公开静态文件提供。

初始内容由当前六个原页面及原摄影数组提取，生成 `20_源码与运行工程/shared/site-content.js`。只有数据文件缺失时才用它初始化；更新种子不会自动覆盖已有网站文档。关于页保留原头像、3 段简介、9 个标签和 6 条经历；摄影总览及各专属分类保留各自原有作品范围。

关闭或重启本机服务，已保存内容仍在文件中；管理员会话需要重新登录。不同浏览器各自登录，内容共享。这里的跨浏览器是访问同一台电脑上同一运行服务，不表示其他设备可直接用自己的 `127.0.0.1` 访问这台电脑。

## 2. 启动、打开和关闭网站

在 `F:\个人主页` 打开 PowerShell：

```powershell
Set-Location -LiteralPath 'F:\个人主页'
node start-server.js
```

服务启动后打开 [本地首页](http://127.0.0.1:5173/Home/index.html)。根目录的 `start-local.bat` 也保留为启动入口。关闭对应命令窗口，或按 `Ctrl+C`，可停止由该窗口启动的服务；停止服务不会删除网站内容。

| 首页 | [打开首页](http://127.0.0.1:5173/Home/index.html) |

日常固定使用上表的 HTTP 地址，便于确认访问的是同一服务。直接双击网站单页的 `file:` 模式不适合作为前后台联动入口。换浏览器无需复制 CMS 数据，但需要各自登录；打开其他端口或另一份部署副本时，应先核对它使用的服务和数据目录。

## 3. 登录与所有页面通用的操作

统一使用 `/admin/index.html` 登录。旧的 `AdminLogin`、`backendProject`、`backendContact`、`backendMessages` 等入口已转向对应统一后台入口。

本轮更新后，按以下顺序操作：

1. 刷新原先已经打开的 [管理后台](http://127.0.0.1:5173/admin/index.html)，让页面载入当前代码。
2. 使用原有账号登录，默认数据来源应为“本机网站（共享保存）”；本说明不复制口令。
3. 确认后台左下角显示“本机网站共享内容”，再进入需要修改的对应页面。
4. 点击“保存本页到网站”，等待“本页已保存到本机网站（版本 N）”提示，然后切回或刷新对应前台；修改关于页时刷新 [http://127.0.0.1:5173/about/index.html](http://127.0.0.1:5173/about/index.html)。

| 按钮或提示 | 实际含义 | 建议操作 |
| --- | --- | --- |
| 保存本页到网站 | 本机网站模式的保存按钮，经 API 写入本机共享文件，并携带读取时的版本号 | 等待成功后刷新对应前台 |
| 保存本页到云端 | 正式云端模式的保存按钮 | 正式网址使用此按钮；本机5173继续使用“保存本页到网站” |
| 本页有未保存修改 | 当前页还有内存中的草稿 | 切换页面、关闭或刷新前先保存，或导出草稿 |
| 撤销本页修改 | 恢复本页最近一次读取或保存的内容，丢弃本页未保存修改 | 不是恢复内置默认，也不会立即执行一次保存 |
| 查看前台 | 打开当前后台页面对应的前台页面 | 保存后刷新核对；摄影分类还要点进对应分类 |
| 导出数据备份／导出当前数据备份 | 下载当前编辑数据的 JSON，包含尚未保存的草稿、留言和内部备注 | 按私人资料保管；导出不等于保存，也不包含媒体文件本体 |
| 退出登录 | 结束当前管理员会话；已保存内容保留 | 有未保存修改时按提示处理，可先取消退出并导出或保存 |

保存成功后，“显示”且允许公开的内容即可被同一服务的前台读取；没有一个额外的发布按钮替你暂存全部修改。未准备好的条目使用“草稿”或“归档”。公开投影会过滤草稿、归档和隐藏内容，不包含留言与内部备注。

添加、上移、下移和移除条目后都要保存当前页。保存前可用“撤销本页修改”恢复；移除 CMS 条目不等于删除电脑上的源照片，也不会自动清理已上传媒体。发生版本冲突会返回 409，本次保存不会覆盖其他会话已经保存的更新。

## 4. 各后台页面分别编辑什么

### 首页

首页管理主标题、档案编号、所在地、印章、向下浏览提示、原片与成片对照和页脚。首屏照片条自动读取摄影总览范围内的精选作品；日期自动显示北京时间当前日期。

1. 编辑“首页主标题与档案”。默认选中照片位置填写正整数，超出精选数量时使用最后一张。
2. “管理摄影精选”进入摄影页。将作品的“前台显示位置”勾选“摄影总览”，再勾选“精选作品”并设置“排序（较小在前）”，保存摄影页。分类页专属精选不计入首页。
3. “Selected frames”显示当前序号、总数和照片名称。点击编号或用方向键、Home／End 切换；手机横向滑动会同步索引。无精选时显示空态。
4. 下方“原片与成片对照”可编辑标题、照片标题、原片图片、成片图片、两张图片说明，以及光线／色调／细节三条观察说明。图片可填写有效地址或使用现有上传入口；请选择同一照片导出的未处理图与成片，尺寸和构图尽量一致。源 RAW 文件自行保留，不直接用于网页对比。
5. 下方默认显示首页精选的第一张照片；点击上方照片、编号或用方向键选片后，对照区同步切换并恢复中间分界位置，悬停不切换下方。成片图片须使用对应精选作品的同一图片地址；选中该作品且配齐不同资源地址的原片时，直接对照提供的图片，不附加模拟调色。其他照片明确显示“交互示例”，以所选照片模拟效果，不代表真实修图前后。无精选时提示暂无照片，不改用其他图库图片。
6. 访客可拖动分界线，或点击“原片／对比／成片”切换。聚焦滑杆后方向键微调，Home／End 查看单侧；手机横向拖动比较，纵向手势仍可滚动页面。图片加载失败会提示并暂停对比操作。
7. 在“本页模块显示”中控制“原片与成片”，保存后刷新首页核对。图片与观察说明会公开展示，请使用准备公开的内容。

旧首页分类入口、手选名单、固定日期与简介卡数据保留，当前首页不再读取；摄影分类页和作品仍由摄影后台维护。新模块的交互示例与后台真实保存分开判断：当前本机正式内容尚未配置真实原片成片对照。

### 关于页

关于页管理姓名、身份、所在地、合作状态、邮箱、肖像、个人简介、技能标签和经历时间线，也可编辑页面标题、肖像说明、资料标签、章节标题、档案编号和页脚。所在地统一在基本资料填写，资料表与顶部档案一起更新；留空时两处都显示待补充。相框两侧文字及其编辑入口已移除。

Today 自动显示北京时间当前日期，跨午夜或重新回到页面时更新，无需手动填写。桌面双栏下肖像相框与技能区底部对齐；窄屏保持上下排列。技能标签悬停显示取景框，单击定格为橄榄绿，再次单击取消；支持键盘和触控，并遵循减少动态设置。

资料标签和值按首行基线水平对齐。时间线可直接单击圆点或卡片选择经历：细线与指示环跟随选择，节点有短暂波纹，卡片有轻抬和局部扫光；悬停可预览对应项。前后箭头、方向键、Home／End、Enter／Space 和触控均可操作，减少动态时保留静态选中状态。

1. 在“关于页基本资料”填写真实信息；“个人资料简短介绍（供搜索读取）”与正文“个人简介”按各自用途填写。
2. 技能标签逐项添加、改名、删除和上下移动。经历时间线可新增条目，填写日期、标题、地点、说明和类型，并调整顺序或显示状态。
3. 保存后核对肖像、邮箱链接、完整简介、技能及时间线的前后浏览。

初始资料恢复自原关于页，不用另一份手写默认替代。关于页邮箱与联系页邮件卡片是不同内容，需分别核对；页面中原有资料的真实性仍由站主确认。

### 项目页

项目页管理页头、档案、展览、页脚、项目卡片和项目选片清单。项目列表每页最多 6 个，点击进入对应详情；详情照片每页最多 6 张。照片资料统一由摄影作品库管理，不再在项目页重复编辑同一张照片。

1. 添加或选择项目，填写名称、主题、介绍、封面、地点、年份、关联摄影分类与查看按钮文字。项目卡片自动进入本站对应详情。
2. 项目只用一个“前台状态”选择显示、草稿、隐藏或归档，并调整项目顺序；原有隐藏状态不会因修改名称等资料而公开。
3. 在“项目照片”添加已有作品或上传新照片，用上移、下移调整顺序。“移出项目”只解除当前关联，作品仍保留。
4. 修改照片名称、图片、说明或公开状态时，点击“到摄影作品库编辑 →”。系统准确定位作品并清除旧查找条件，可用“返回项目”回到原清单；有未保存内容时按提示保存或取消。
5. 保存项目选片后，打开“查看此项目详情”核对。项目照片采用明确的关联清单，不自动加入整个分类。

### 摄影页：作品与关联分类页

摄影总览和摄影分类集中放在一个后台页面维护；每件作品的分类归属与展示范围分别保留。初始摄影总览 **11 件**、人像 **8 件**、风景 **10 件**、个人 **10 件**，不把总览作品自动混入三个专属分类。当前 City Humanity 与人像、风景、个人一样，通过摄影页的分类卡片打开。旧城市专题已退役，旧网址转到当前 City Humanity；旧独立数据与原素材保留用于恢复，不再编辑、发布或单独统计。

1. 在“摄影作品”上传或批量导入图片，填写名称、主要分类和显示状态。作品库每页最多 12 件缩略图，支持搜索、按分类和状态查找；点击缩略图编辑，不再把所有照片挤在左侧长列表。
2. 勾选“展示页面（可多选）”中的对应页面，再决定是否设为精选；新作品默认草稿。照片说明、排版和拍摄参数放在选填折叠区，切换作品、查找和翻页不会丢掉已输入的草稿，最后保存本页。
3. 设置“精选作品”、卡片布局、排序与显示状态。新建作品先保留“草稿”，检查后再设为“显示”。
4. 在“分类管理”维护入口名称、分类页标题、唯一的分类介绍、封面、档案编号和搜索摘要。入口卡片只显示名称与数量，卡片封面和分类页首屏封面按用途分别设置。每个分类首屏只显示一张“分类页封面”，留空使用分类卡片封面；Personal 也在这里编辑，原“三张装饰照片”入口已移除。摄影页日期时间自动显示北京时间，无需手填。
5. 分类只用一个“前台状态”选择显示、草稿、隐藏或归档；旧的两个公开开关已整合。隐藏分类会连同其关联作品从公开展示中排除；改名后仍通过分类关联标识定位，数量取当前公开作品。
6. 前台只保留分类卡片入口，不再出现 Filter 或分类内风格筛选。保存后检查总览、对应分类、分类首屏、精选、排序、网格／列表和照片详情；清空专属分类作品后不从总览补回。

摄影分类可用 `?category=真实分类标识` 直接定位分类，例如 [人像分类示例](http://127.0.0.1:5173/photography/index.html?category=portrait)。自建分类的标识以实际关联为准，不要把页面上装饰性的 `/photography/portrait` 文字当成独立服务器路由。

摄影总览右上角按本页 FEATURED 的同一名单循环展示精选照片，采用四片形变切换并沿用网站纸色；点击图片切换下一张，可用暂停按钮停止自动播放。悬停、键盘聚焦、页面不可见或减少动态时暂停自动切换；减少动态时显示完整静态照片。没有精选时显示空态，单张时不自动轮播。

图库总览和各分类作品均支持分页。网格按当前列数、横幅／竖幅占用量控制在三行容量内；列表桌面每页 6 张、窄屏每页 4 张。使用上一页、页码或下一页切换，不足一页时边界按钮置灰；切换分类和排序回到第一页。详情前后浏览、FEATURED 选片、网格／列表切换及窗口变化会同步到选中照片所在页，后台设置的默认选中照片保留。

“访客交互设置”可设置默认排序、默认视图、是否允许收藏及“摄影页照片放大查看”。放大开关只管摄影页，项目详情保留独立的大图查看。收藏只保存在访客自己的浏览器，不会上传或跨设备同步；它与管理员设置的“精选作品”不同。

### 旧城市网址兼容

旧城市专题的独立页面、编辑入口和统计已移除。访问 /CityHuman/index.html 会转到 /photography/index.html?category=city-humanity；旧后台 #city 会转到摄影页管理。当前 City Humanity 仍在“分类管理”和“摄影作品”编辑，原来的 9 条独立记录不自动混入当前分类；其数据、原素材和源码恢复备份保留。


### 联系页

联系页管理标题、介绍、年份范围、所在地、语言、回复时间、接单状态、联系卡片、留言表单、胶片照片条和页脚。

1. 编辑联系页资料及工作状态。回复时间与接单状态是你填写的说明，不是自动检测。
2. 联系卡片可选择邮件、微信、二维码或普通链接等类型，填写账号、URL、说明、按钮文字、图片、排序和显隐；保存后逐个检查。

4. 联系页胶片条自动读取摄影总览范围内的精选作品并按排序循环滚动，与首页共用名单，不再手动挑选五张。到摄影页设置“摄影总览”“精选作品”和排序；胶片支持暂停／继续，悬停、聚焦或页面不可见时停止滚动，减少动态时可静态横向浏览。无精选显示空态，单张保持静态；旧胶片数据保留。修改二维码图片不等于修改二维码内部编码的信息。
5. 保存后检查联系按钮、复制信息、表单校验、工作状态和照片条。

本机联系页通过真实同源联系接口提交，服务端保存后才返回成功；留言进入同一共享网站的收件箱，可由其他已登录浏览器读取。当前没有已验收的邮件、短信或微信通知链路；测试时使用明确的测试内容。

## 6. 图片、草稿与一次更新的顺序

### 本机网站图片上传

正常本机网站模式通过真实上传接口保存图片，支持 **JPEG／PNG／WebP／GIF，单张不超过 8 MB**；网站文档上限为 **32 MB**。媒体保存在 `20_源码与运行工程/.local-db/media/`，不把图片本体塞进浏览器存储，处理不修改电脑上的源照片。

选择文件时可能已经执行上传；未保存内容、撤销编辑或移除条目不等于撤回已上传媒体。媒体地址可供前台读取，草稿与隐藏状态不提供图片文件保密。原始照片与工程应另行保留。

### 建议顺序

1. **先备份。**导出当前 JSON，原照片另行保留；重要批量修改前，由维护者备份网站数据文件及媒体目录。
2. **逐页编辑。**先整理分类与作品，再选首页入口、项目跳转和联系信息。
3. **保存当前页。**等待成功反馈，再打开前台刷新；失败或版本冲突时保留草稿。
4. **核对相关流程。**检查标题、图片、分类直达、分页、详情、导航和联系按钮；布局变动再看桌面与窄屏。
5. **需要上线时单独发布。**核对 `dist/client`、Worker 配置、正式数据和恢复能力，完成部署与真实环境验收。

## 7. 导出、恢复与常见故障

### JSON 与完整网站备份

后台的“导出数据备份／导出当前数据备份”下载当前编辑状态的 JSON，可能包含未保存草稿和私人留言；导出不代替保存。**JSON 不包含已上传图片文件，因此不是共享网站的全量恢复包。**

完整恢复应同时保留 `20_源码与运行工程/.local-db/wong-cms.json` 与 `20_源码与运行工程/.local-db/media/`。每次写入前，服务会在 `20_源码与运行工程/.local-db/recovery/` 保留被替换文档的原始字节与 SHA-256，供维护者定位与核对。恢复文件同样含私人内容，不公开、不纳入 Git。

**当前没有一键导入备份功能。**恢复前先保留当前文件和媒体，由维护者核对来源、版本、图片引用与恢复范围；恢复时先停止所有使用该数据目录的服务，避免写入冲突。真实云端恢复还需分别考虑 D1 内容与 R2 媒体，本轮未做生产恢复演练。

### 旧浏览器内容

原浏览器的 `localStorage` 数据仍保留，没有因切换共享保存而清空。需要留档时，使用后台提供的旧版浏览器备份导出入口；旧浏览器 JSON 与当前共享网站数据可能不同，不能直接当成全量恢复文件。

旧浏览器适配仅用于兼容、隔离测试和离线旧稿，不是正常服务的登录及保存方式。日常使用“本机网站（共享保存）”，不要为找回旧内容而清空存储或反复切换来源。浏览器存储的来源隔离规则可参考 [MDN localStorage 文档](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。

### 常见故障

| 现象 | 优先检查 |
| --- | --- |
| 地址打不开或拒绝连接 | 服务是否仍在运行，是否在项目根目录启动；不要直接双击网站单页 |
| 提示端口被占用 | 先打开原地址，可能已有服务；不要随意结束其他进程 |
| 保存后前台未变化 | 先刷新旧后台，确认左下角“本机网站共享内容”；确认保存成功，再刷新上表对应前台，核对条目、分类和模块是否允许展示 |
| 换浏览器看到不同内容 | 是否访问同一台电脑上同一运行服务，是否误开其他端口、旧发布副本或离线旧稿；正常共享模式无需复制浏览器数据 |
| 新照片看不到 | 是否仍是草稿，所属分类和展示范围是否匹配，当前查找条件是否匹配，图片是否读取成功 |
| 清空列表后仍看到旧内容 | 先确认保存成功、前台已刷新且未打开旧发布副本；当前页面应保留空列表，不应恢复旧示例 |
| 暂停留言后不能提交 | 检查“接受前台留言”开关和设置的暂停说明 |
| 保存失败或内容过大 | 保留当前页并导出草稿；检查提示、32 MB 文档上限、磁盘空间与目录写入权限，不删除业务数据 |
| 提示 401 或登录失效 | 先导出未保存草稿再登录；服务重启后会话需重登，已保存内容保留 |
| 提示 409 或已有更新 | 本次未覆盖共享内容；先导出草稿，再重新读取最新状态，核对差异后编辑保存 |
| 提示 400 或数据结构无效 | 当前提交未保存；保留草稿，由维护者检查字段结构，不用强制覆盖绕过校验 |
| 提示 503 或数据文件损坏 | 保留原文件及恢复副本，由维护者核对与恢复；不要删除文件让服务重新初始化 |
| 提示写入锁异常 | 由维护者先停全部使用该数据目录的服务，保留原件并将 `write-lock` 目录改名保存，再排查恢复；不要删除业务数据 |
| 留言成功但未收到邮件 | 成功表示服务已接收并保存，可到共享收件箱检查；当前没有已验收的邮件通知 |

### 前台照片保存限制

七个前台入口（包括项目详情）共用图片保存限制：拦截图片右键菜单、原生拖拽、图片资源链接的点击下载、Ctrl／Command＋S，以及选中图片的复制；选择中同时有文字时保留纯文字。普通文字复制、微信号复制、照片点击放大、翻页、拖动对比和触控浏览继续可用。后台上传和数据备份下载不受影响。移动端加入长按另存菜单的抑制样式，Safari／iOS 真机效果尚未验收。

网页要显示图片，就会把展示图片发送到浏览器。这些措施只能减少直接保存入口，无法彻底阻止截图、从网络请求获取图片、通过浏览器菜单保存或关闭脚本后的操作。原图片和素材文件保持原样。更新后刷新前台生效。

## 9. 当前同源接口约定

以下接口由当前本机服务实际提供，前后台共用；正式云端沿用兼容约定，但仍需单独部署验收。管理员接口要求同源会话，跨来源 API 请求会被拒绝。

| 用途 | 请求 | 操作边界 |
| --- | --- | --- |
| 识别本机服务 | `GET /api/cms-status` | 用于识别本机共享保存能力 |
| 管理员登录 | `POST /api/admin/login` | 服务端验证并建立会话；本机服务重启后重新登录 |
| 检查会话、退出 | `GET /api/admin/session`、`POST /api/admin/logout` | 同源会话 Cookie |
| 读取内容 | `GET /api/admin/state` | 管理员读取当前共享内容与版本 |
| 保存内容 | `PUT /api/admin/state` | 携带版本号，冲突返回 409；结构无效不写入 |
| 图片上传 | `POST /api/admin/upload` | 本机保存到媒体目录并返回地址；正式 R2 行为待部署验收 |
| 访客读取 | `GET /api/public-state.js` | 公开投影过滤草稿、归档、隐藏内容，不含留言和内部备注 |
| 内容版本检查 | `GET /api/public-version` | 按后台设置检查新版本，不等于另做一次保存 |
| 前台留言 | `POST /api/contact` | 服务端保存确认后返回成功；不表示发送了通知 |

公开投影与媒体访问是两个范围：不出现在前台的条目，其已存在的媒体 URL 仍不能当作私密存储。私有业务文档、恢复文件和管理员内容不会作为公开页面文件读取。
