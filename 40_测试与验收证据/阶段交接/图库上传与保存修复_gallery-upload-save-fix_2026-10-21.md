# Gallery 上传与保存修复

事项日期：2026-10-21（Asia/Shanghai）。沿用当前 `codex/wong-motion-effects` 分支，修改前恢复点为 `71f70e5`（`local/2026-10-20.004`）。

## 原因与证据

在隔离浏览器复现了相同现象：同一个小 PNG 连续选择、保存两次都正常，选择器连续四次都能打开。约 2,618,723 字节的 JPEG 第一次保存成功，第二张相同体积的 JPEG 保存时触发 localStorage 的 QuotaExceededError。界面显示 10 张，实际保存仍为 9 张，存储 JSON 长度停在 3,504,504 字符，界面残留上一次成功提示。由此确认保存容量与异常反馈存在缺陷，不是上传按钮只允许使用一次。

[修复前后实际输出](../图库上传验证_gallery-upload-verification_2026-10-20/图库上传回归结果_gallery-upload-regression-result_2026-10-21.json)；输出仅含合成图片、条目数量及错误类型，不包含账号密码或用户图片。

## 修改范围

- `20_源码与运行工程/admin/script.js`：Gallery 新导入和替换图片生成轻量本地预览，长边不超过 1600 px，dataURL 不超过 512 Ki 字符。较小图片保留原编码，合规 GIF/SVG 保留格式；超限 GIF/SVG 明确拒绝，不静默栅格化。
- 导入按顺序处理，整批结束后重绘；等待期间暂停 Save Changes、Reset 和重复导入。异步结束不覆盖用户切换后的 Projects 视图，新图片不会被当前筛选隐藏。
- Save Changes 捕获容量及存储不可用错误，保留上一次已保存数据、内存草稿和未保存标记；失败不显示成功，解除限制后可重试。Reset 同样不会误报保存成功。
- `admin/styles.css`：仅添加处理期间的禁用状态样式；页面布局保持原样。
- [独立回归脚本](../../20_源码与运行工程/admin/测试_tests/图库上传回归_gallery-upload-regression.cjs)：只允许本机预览地址，创建独立浏览器会话和内存图片，不修改现有用户浏览器会话。
- 没有改后端、认证、共享存储契约、数据库、依赖或部署配置。没有压缩既有图库记录，没有修改用户原照片文件。

## 实际验证

图库专用回归的六组场景全部通过，未捕获页面未处理异常：

1. 同一文件重复选择、连续大图导入、批量导入、筛选复位和原记录保持不变。
2. 图片替换、小 PNG 原编码及透明通道内容保留、保存后刷新与实际图片解码。
3. 导入时 Save/Reset 禁用，切换 Projects 后不会被异步上传重绘，Projects 和图库可一并保存。
4. 损坏图片及超尺寸 SVG 明确失败，合规 SVG 保留格式，部分失败后可继续上传。
5. 真实浏览器容量超限时，已保存内容逐字保持不变，草稿仍存在；释放测试占位后再次保存成功，原有大图记录不被重压缩。
6. 模拟 SecurityError 后仍保留草稿及已保存内容，恢复存储能力后可成功保存。

相同约 2.6 MB 合成 JPEG 的新预览长度为 362,231 字符，约 0.27 MB；连续四张及多次保存通过。该数字只针对测试图片，不代表所有照片的压缩率或无限容量。

`node --check`（管理脚本和回归脚本）、`git diff --check` 通过。[1074×892 实际截图](../图库上传验证_gallery-upload-verification_2026-10-20/图库上传修复_gallery-upload-fixed_2026-10-20.png) 已检查，样式与既有图库一致。

独立只读审查发现 GIF/SVG 可绕过长边上限，已补齐明确拒绝并增加对应回归。未发现其他明确新增数据覆盖或保存失败误报成功问题。

## 重跑方式

先保持 `node start-server.js` 的本机预览运行。当前机器可在项目根 PowerShell 中运行以下命令；环境变量仅作用于当前终端：

```powershell
$env:NODE_PATH='C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules'
$env:CMS_TEST_BROWSER_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
node '20_源码与运行工程/admin/测试_tests/图库上传回归_gallery-upload-regression.cjs'
```

默认目标为 `http://127.0.0.1:5173`；可用 `CMS_TEST_URL` 指定另一个本机端口。无需安装新依赖。脚本会关闭自己创建的浏览器，不会清空真实浏览器的 localStorage。

## 使用与恢复边界

更新需刷新原后台标签页，但本次没有自动刷新正在编辑的用户页面。旧脚本内尚未保存的编辑无法自动迁移，刷新前应留存未保存的内容或原始图片，随后重新导入未保存项。

当前仍是浏览器本地模拟图库，不是原图云存储；容量满时会提示并保留当前页草稿。关闭页面不会把失败的保存自动变成成功。已有成功保存数据不会被自动清理或重压缩。

回滚时先检查当前差异，再反向应用本次本地提交；不清理浏览器存储、不覆盖用户数据。此修复没有存储结构迁移，旧代码仍可读取已保存预览。
